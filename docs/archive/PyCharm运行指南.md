## 2.5 两个必踩的坑（2026-10-09 现场遇到，已做成工具）

### 坑 1：`ollama serve` 报「11434 端口只允许使用一次」→ **这不是错误**

原因：你的 **Ollama 桌面版/后台服务已经在跑了**，端口被它自己占用。
手动再执行 `ollama serve` 就会撞上这个报错。

**怎么判断在不在跑**：跑一下 **`0. 端口/服务自检`**，第 1 节会明确告诉你：

```
[1] 本地大模型（Ollama, 11434）
  已就绪（HTTP 200），检测到 qwen2.5 模型
  ✅ 不要再去执行 `ollama serve` —— 报 "11434 被占用" 是正常的，服务已经在跑
```

**所以：看到这个报错就说明大模型好了，直接跑服务器即可，什么都不用做。**

### 坑 2：起服务器报 `[Errno 10048] bind on address ('0.0.0.0', 8080)`

原因：**上一次的服务进程没关掉**（比如之前用命令行起过、或 PyCharm 里上次的 Run 没停），
端口还占着。注意这时模型其实**已经加载成功**了，只是最后一步绑定端口失败了。

**三种处理（任选一种）**：

1. **最省事**：跑 **`0. 端口/服务自检`** → 它会打印占用的 PID 和进程名；
   再用 `Edit Configurations → Parameters` 填 `--kill`、或直接：
   ```
   Tools → Terminal →  python tool/port_check.py --kill
   ```
   （它只杀占用 8080/8443 的 **python 进程**，不会碰 Ollama）
2. **PyCharm 内**：底部 **Run** 面板，把所有还在跑的服务全部点红色 ⏹ 停掉，再重新 ▶；
3. **换端口**：运行配置 `6. 服务器（纯 HTTP）` → `Edit Configurations` → `Parameters` 填 `--port 8090`，
   然后手机/浏览器访问 `http://<IP>:8090/m`。
   ✅ 已确认：换端口后**手机页里内嵌的接口地址会自动变成 8090**（页面不再写死 8080），不用改一行代码。

### 我已经在代码里做的加固（不用你动手）

| 改动 | 作用 |
| --- | --- |
| **打开设备 ≠ 等第一帧**（`camera_source.py`） | **这是本次真正的 bug**。旧代码把两件事挤在同一个超时里：相机冷启动要 3 秒才吐第一帧，多策略尝试时预算被吃光 → 判成"打不开"。现在 `start()` 只负责"打开成功"，首帧交给后台采集线程继续等 |

| **逐步日志** | 控制台会打印「开始打开（source=1 期望 1280x720 MJPG）」「index=0 backend=dshow fourcc=MJPG: 成功」这类行 —— 哪一步失败一目了然 |
| **`probe_timeout` 3 → 8 秒** | 实测依据：索引 1 冷启动 **3.0 秒**、索引 0 **2.0 秒**。调小会把"只是启动慢"的相机误判成打不开 |
| **失败不再弹模态框** | 旧版打不开会弹 `QMessageBox`（阻塞事件循环 = 看起来死机）。现在把原因写进界面 + 建议区，并**后台自动扫可用索引**回报结论 |
| **无帧不再静默** | 实时检测中拿不到帧会更新状态并触发诊断，不会出现"画面冻住、什么都不说" |
| **`tool/camera_check.py`**（运行配置 7） | 一键诊断：DirectShow 枚举 + 索引×后端×格式全组合 + 按设备名打开 + 抓帧存盘 + 给结论 |

### 2.6.1 画面卡 / 帧率低 / 一会儿就不动（2026-10-09 已优化）

**症状**：能出画面但很顿、鼠标拖动窗口发滞、跑一会儿画面不动了。

**根因（我实测确认）**：旧版界面每 30ms 就把最新帧**完整处理一遍**：

```python
ok, frame = camera.read()    # 每拍拷贝 1280×720×3 = 2.76MB（33拍/秒 ≈ 91MB/s）
display = frame.copy()       # 再拷一份
show_frame(display)          # 再做 BGR→RGB + QImage + 缩放（又是几个 ms）
```

等于每秒做 33 次大图彩色转换 + 缩放，CPU 被吃满 → 界面顿；等相机/线程一忙，就"看起来不动了"。

**已优化**（现在是帧驱动 + 限频）：

| 优化 | 效果 |
| --- | --- |
| **只在有新帧时渲染**（用采集线程的帧序号 `seq` 判重） | 不再反复渲染同一帧 |
| **零拷贝取帧**（`peek()`） | 省掉每拍一次 2.76MB 拷贝 |
| **渲染限频**：`CAMERA.display_fps`（默认 15） | 从 33 次/秒降到 15 次/秒 |
| **预览缩放**：超过 `CAMERA.display_max_side`（默认 960）先等比缩小 | 再省一笔 CPU |
| **无检测框时不拷贝**（直接显示原帧） | 又省一次全帧拷贝 |
| **状态栏实时回显** | 每 2 秒显示 `摄像头已打开 1280x720 25.1fps 帧龄0.04s` —— **一眼分辨是"相机慢"还是"界面慢"** |

**调参建议**（`config/configs.yaml` → `CAMERA`）：

```yaml
CAMERA:
  width: 1280          # 机器弱可以降到 640x480，CPU 立竿见影
  height: 720
  display_fps: 15      # 还想更省 → 10
  display_max_side: 960  # 还想更省 → 720
  stale_sec: 2.0       # 看门狗判"卡死"的阈值；USB 相机偶发几秒断流可调到 4.0
```

**怎么判断"是谁慢"**：看状态栏那行字。

| 状态栏显示 | 含义 | 处理 |
| --- | --- | --- |
| `25fps 帧龄0.04s` | 相机正常，界面渲染也跟得上 | —— |
| `fps` 很低（如 3~5） | **相机本身慢**（USB2 口/曝光长/格式不对） | 换 USB3 口、把 `fourcc` 换 `YUY2`、分辨率降到 640×480 |
| `帧龄` 持续 >2s 且被"换 handle 自愈" | 相机断流（线材/供电/占用） | 换线换口；把 `stale_sec` 调大一点避免频繁重开 |
| 状态栏 normal 但界面还是顿 | 界面/CPU 瓶颈 | 降 `display_fps`、降 `display_max_side`、降分辨率 |

> 提示：YOLO 推理本身在后台线程（GPU 上 ~0.02 秒/张），**不是**界面卡的原因；
> 别把 `infer_fps` 调很低来"治卡"，那只会让检测框更新变慢。

## 5. 常见问题（PyCharm 版）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| **点「打开摄像头」像卡死 / 没反应** | 这台机器**没有可用相机**（实测 0~3 号索引全部打不开）；旧版还会因此弹模态框，看起来就像死机 | 已修：不弹框、状态写界面、后台自动扫索引。没有相机就用「打开图片/文件夹/视频」，详见 **2.6 节** |
| `No module named 'torch'` | 解释器不是 pest-gpu | 右下角切解释器（见第 1 节） |
| `FileNotFoundError: ./config/configs.yaml` | **工作目录被改错**了 | Run → `Edit Configurations...` → `Working directory` 必须是 `D:\CropGuard`（即 `$PROJECT_DIR$`） |
| 运行时报 `NameError: name 'background_img' is not defined` | 老版本遗留 bug | 已修；如果还报，说明你跑的是旧文件，重新拉一次代码 |
| 右键文件 → Run 后 GUI 报 `yolo` 相关错误 | 用"右键 Run"跑的是**别的**脚本（如 `main.py` 之外） | 用第 2 节里的配置跑；`main.py` 必须作为主脚本运行 |
| 服务器起不来：`Address already in use` | 8080 被上次没关的进程占着 | Run 面板把所有运行中的停止（⏹）；或改用 `6. 服务器（纯 HTTP）` 并加参数 `--port 8090` |
| 手机上打不开 | 不在同一网段 / 地址不对 | 手机连同一 WiFi；IP 用 Run 窗口打印的那个（换网就会变，**重启一次服务看新日志**） |
| 手机 HTTPS 提示证书不受信任 | 自签证书 | 点"高级 → 继续访问"（正常流程） |
| 没有语音 | 音频设备/后端问题 | 看 Run 窗口 `[TTS] 后端就绪 engine=...`；显示"无可用语音后端"才需要排查 |
| 相机打不开 | 索引不对 / 被别的程序占用 | 跑 `5. 找摄像头索引`，看 `output/camera_probe/` 里的快照，把对的索引填进 `configs.yaml` 的 `CONFIG.camera_num`；关掉微信/QQ/浏览器/另一个 Python 进程 |
| 想在 PyCharm 里调试断点 | — | 用 **Debug ▶🐞** 按钮代替 Run，效果一样只是会停断点（大模型调用处不建议断，会等很久） |

## 6. 三个必须记住的规则

1. **别让 GUI 和服务器同时开同一个相机**（Windows 相机独占，后开的那个会失败）；
2. **工作目录永远是项目根目录**（`D:\CropGuard`），改错就找不到配置和模型；
3. **喷洒永远要点"确认"**：大模型说的话不会自动执行，这是刻意的安全设计。
