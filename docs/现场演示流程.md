# 现场演示流程 · 推理 + 设备联动闭环（你这一棒）

> 适用：2026 睿抗 CAIR 国赛现场。分工：**你 = 推理 + 设备联动闭环**；路演、PPT、答辩 = 队友。

## 0. 一页速查卡（上台前贴在桌上）

```
起服务：  $env:CG_DEVICE='cpu'; py -3.14 api_server.py
定点联动：http://127.0.0.1:8080/stream        ← 自动喷淋只在这条路上
20样本：  py -3.14 main.py                     ← 先关掉 /stream 标签页（相机独占）
手机闭环：https://<启动横幅里的IP>:8443/m
自检：    py -3.14 tool/port_check.py          （--kill 杀占用 8080/8443 的进程）
认相机：  py -3.14 tool/camera_probe.py        （看 output/camera_probe/cam_?.jpg）
节点状态：http://127.0.0.1:8080/api/mist/status
```

**三句话心理锚点**
1. 我只负责：虫子放上去 → 屏幕出框出风险 → 设备动 + 语音响。其余不归我。
2. 一切"自动"只发生在**实时画面**这条 WebSocket 路上；**上传图片永远不会喷**。
3. 相机是独占资源：**同一时刻只能有一个进程或页面开着 PC 相机**。

## 1. 先背下来：谁触发谁（现场 90% 的慌乱都源于搞错这张表）

| 入口 | 你能干什么 | 会喷淋吗 | 占 PC 相机吗 |
| --- | --- | --- | --- |
| `main.py`（GUI） | 打开图片/文件夹/视频/摄像头、**📷拍照识别、现场评测面板（计时+判分+导出报告）**、AI 建议、提问 | ❌ **一行喷淋代码都没有** | ✅ 占 |
| 网页 `/stream` | PC 定点实时画面、风险条、**手动喷淋按钮**、当前检测、联动历史 | ✅ 中/高风险**自动喷** | ✅ 占 |
| 手机 `/m` 实时模式 | 手机摄像头逐帧识别、叠框、截图 | ✅ 中/高风险**自动喷**（与定点同口径） | ❌ 不占（用手机相机） |
| 手机 `/m` 拍照模式 | 拍照上传 → 带框结果图 + 风险 + 建议 | ❌ 不喷 | ❌ |
| 网页 `/`（首页） | 上传文件检测、手机端二维码 | ❌ 不喷 | ❌ |
| `/dashboard` | 数据看板（KPI/曲线/27类/20样本/闭环口径） | ❌ **只读**，无写接口 | 只有点"实时画面"才占 |
| 手机/网页喷洒按钮、`/api/ask_command` 确认 | **人工触发**喷淋 | ✅（必须人工确认） | ❌ |

**由这张表推出的三条现场决策**
- 要演"自动联动" → 必须走 **`/stream`（PC 相机）** 或 **手机实时模式**；用"上传图片"演不出来。
- 要让 GUI 拿到相机 → **先把浏览器里 `/stream` 那个标签页关掉**（WS 断开 → 引用计数归零 → 相机释放），**服务器不用重启**。
- 手机实时模式与 GUI **可以同时开**：一个用手机相机、一个用 PC 相机，不冲突。这是你的"并行救命通道"。

## 2. 上台前 40 分钟 · 六项硬自检（每项都有"过关标准"）

> 顺序不能换：先认相机、再认节点、最后起服务（config 只在启动时读一次）。

### ① 清场（30 秒）
关掉微信 / QQ / 相机 App / 其它 python 进程 / 之前遗留的服务窗口。
```powershell
py -3.14 tool/port_check.py        # 期望：8080/8443/11434 状态清晰，Ollama 已就绪
py -3.14 tool/port_check.py --kill # 只有被占时才用；它只杀占 8080/8443 的 python，不动 Ollama
```
**过关标准**：11434 显示"已就绪（HTTP 200，检测到 qwen2.5）"；8080/8443 空闲。

### ② 认相机（2 分钟）——**这一步不做，后面全白搭**
```powershell
py -3.14 tool/camera_probe.py
```
输出里会先给"索引 ↔ 设备名/VID"对照表，再把每个索引的快照写到 `output/camera_probe/cam_?.jpg`。
- 打开快照**肉眼确认**哪张是外接工业相机（对着样本台的那张）；
- 把它的 VID 写进 `config/configs.yaml` 的 `CONFIG.camera_device`（如 `'vid_0c45'`）——**别写死数字索引**（实测索引被插拔重排过，会把内置相机当外接用而"看起来一切正常"）。

**过关标准**：你能指着屏幕说出"索引 N 是外接相机，画面就是样本台"。

### ③ 认节点 IP（5 分钟）——**当前配置里是占位地址，必须改**
节点串口（115200）上电后会打印自己的 IP。把两个片区的真实 IP 填进 `config/configs.yaml`：
```yaml
SPRAY:
  transport: 'http'
  http_targets:
    - { group: 'g1', url: 'http://<片区A真实IP>', protocol: 'mist' }   # 手写 sketch 固件
    - { group: 'g2', url: 'http://<片区B真实IP>', protocol: 'mist' }   # 若走项目固件改成 json + /spray
```
> ⚠️ 仓库里现在是 `172.23.153.231` 且 g1/g2 **指向同一个 IP** —— 这是上次联调留下的占位。不改就会"点了没反应"，而且 `/api/mist/status` 每次要等 1.5 秒超时。
> 改完 **必须重启服务**（config 启动时读一次）。

**过关标准**：
```powershell
# 重启服务后
Invoke-RestMethod http://127.0.0.1:8080/api/mist/status
```
两个节点的 `reachable` 都是 `true`（或节点能收到指令并动作）。

### ④ 起服务（1 分钟）
```powershell
$env:CG_DEVICE='cpu'; py -3.14 api_server.py
```
**横幅逐行对数（4 行都要，缺哪行就知道哪坏了）**：
```
[INFO] Device: cpu                                       ← 设备（本机必须 cpu）
[INFO] Spray transport=http available=True
[INFO] 雾化节点(mist)=['http://<真实IP>', ...] 持续模式兜底=300s   ← 地址对不对，看这里
[CERT] ✅ SAN 已覆盖当前局域网 IP: 10.x.x.x
手机会话页(唯一入口): https://10.x.x.x:8443/m             ← 手机就输这个
语音: engine=powershell ready=True                        ← 不 ready 就查 /api/feedback/status
```
**过关标准**：4 行齐、`available=True`、IP 与手机上看到的一致。

### ⑤ 三项连通性（1 分钟）
```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/health          # model_loaded=true, classes=27
Invoke-RestMethod http://127.0.0.1:8080/api/mist/status     # reachable=true
Invoke-RestMethod http://127.0.0.1:8080/api/feedback/status # tts.ready=true
```
浏览器开 `http://127.0.0.1:8080/stream` → 画面出来、状态点变绿「已连接 · 实时监测中」。
> 无相机时服务端要跑完 DSHOW 多策略探测（约 10 秒）才回原因，**别以为卡死了**，等它给可读的错误。

### ⑥ 试喷一次 + 语音自检（1 分钟）
- 在 `/stream` 点「G1 组喷」→ 听继电器"咔哒"、看雾化出雾、页面历史新增一条；
- 起服务时若听到"语音播报自检，农智云已就绪" → 语音链路活着（本机实测 `engine=powershell`，因为 SAPI 的 COM 播报在本机报错，auto 会自动选可用后端）。

**过关标准**：手动喷 3 秒真的动 + 语音真的响。**这两件都活着，你这一棒就不会 0 分。**

### 幕 ①　定点自动闭环（约 2–3 分钟，最出彩的一场）

| 4 | 指一下下方便刷新"联动/喷淋历史" | 新增一条：`高风险 · 时:分:秒 → 全体喷 3s · 检测到的虫` |

**口播一句**（你的部分，不用长）：
> "这是定点监测：相机常驻，识别到高风险后系统自动联动喷洒，同时语音播报——识别、决策、执行是一条闭环。"

**机理备查**（被追问时用）：推理泵按 `infer_fps=5` 取帧 → `assess_risk()` 纯规则判级 → 中/高风险进联动 → 秒数**查表** `risk_map`（高风险=全体 3 秒、中风险=片区A 2 秒、低/无=不喷）→ 语音与喷淋异步执行，绝不阻塞推理。

### 幕 ②　20 样本限时推理（约 3 分钟，评分主战场）

> 前提：幕① 的 `/stream` 标签页**已关闭**。服务器继续开着（手机端要用），它此时不占 PC 相机。

| 步骤 | 你的动作 | 预期 |

**时间预算（实测口径）**
- CPU 单张推理实测 **139–365 ms**（首张含预热约 2.2 秒）；20 张推理本身 **不到 10 秒**。
- 所以 180 秒几乎全花在"递样本 + 摆正 + 点按钮"上：**5–6 秒/张** 就能在 100–120 秒内跑完，留 60 秒余量。
- 节奏建议：递样 2–3 s → 拍照+出结果 1 s → 确认 1 s。**宁可稳，不要抢**。

**评分口径（你被判分时的依据）**：准确度 = 正确数 × 1.0（满分 20）；时效性满分 10，超时每 1 秒扣 0.5，扣完为止；总分 30。

## 4. 必须绕开的 4 个翻车点（都是我实测撞到的）

1. **节点地址是占位符**：config 里 g1/g2 都指着 `172.23.153.231`（离线，超时 1.5 s）。不改 → 所有喷淋"看着成功、其实没动"。改完**重启服务**。
2. **上传图片不会喷**：`/api/detect`（网页上传/手机拍照模式）只出结果与建议，**不触发联动**。要演自动喷必须走 `/stream` 或手机实时模式。
3. **相机独占**：GUI 与 `/stream` 不能同时开 PC 相机。切换顺序永远是"先关页面/关 GUI，再开另一个"（关标签页即释放，不用重启服务器）。
4. **GUI 的导入顺序不能改**：本机实测 `import PyQt5` 在 `import torch` **之前** → torch 报 `OSError [WinError 1114] c10.dll` 初始化失败。`main.py` 顶部已把 torch 放在 PyQt5 之前（注释里写了 CRITICAL），**别"顺手整理" import 顺序**。

> 另有一条答辩口径提醒（不归你讲，但别被人问到）：问"今天天气怎么样"这类库外问题时，回答是"知识库未涵盖…"，但**依据栏可能显示最近检测过的虫种**——因为 `/api/ask` 会自动带上最近一次检测上下文。这是上下文绑定，不是幻觉；想要干净的拒答演示，就先问库外问题、再放样本。

## 5. 故障速查（现场 10 秒决策，不许低头修硬件）

| 现象 | 你马上做什么 | 同时对评委说 |
| --- | --- | --- |
| `/stream` 画面不出来 | 等 10 秒（无设备探测要这么久）→ 关标签页重开 → `POST /api/camera/restart` → **手机实时模式顶上** | "定点机位在重连，我们同时用手机端看同一套推理。" |
| 节点不动、继电器没声 | 看 `/api/mist/status` 的 `reachable` → 多半是 IP 变了 → **不要现场改配置**，改用语音+历史继续演 | "控制指令已下发，链路反馈正常；节点我在复位，识别端不受影响。" |
| 起服务报 `[Errno 10048]` bind 8080 | `py -3.14 tool/port_check.py --kill` → 重启 | "上一个实例没退干净，已经清掉了。" |
| 手机页打不开 | 用**启动横幅里那句**地址；确认手机和电脑同一网段 | "两个设备要在同一网络，我确认一下。" |
| 手机实时模式点不动 | 多半是证书/HTTPS：检查横幅 HTTPS 是否就绪；不行就留 HTTP 用**拍照模式** | "实时模式需要 HTTPS，我们用拍照模式先跑通闭环。" |
| 没语音 | `Invoke-RestMethod .../api/feedback/status` 看 `tts.engine/ready` | "语音后端在重启，界面反馈正常。" |
| GUI 打不开相机 | `/stream` 标签页没关；或微信/QQ/另一个 python 占着 | "相机被别的窗口占着，我切一下。" |

**保命底线**：规则里"场景化反馈"是**物理动作 或 信息反馈二选一**。
→ **喷淋全废也不怕，只要语音还在响 + 界面还在出框出风险，这 5 分就保住。** 先确认语音，再从容排错。

## 7. 你这一棒可能被追问的 3 个问题

1. **"为什么喷 3 秒？谁定的？"** → 秒数由配置表 `risk_map` 查表得出，不由大模型自由生成（保证可复现）；单次上限 5 秒，后端和固件各钳一次（雾化片怕连续通电）。
2. **"CPU 没有显卡，180 秒来得及吗？"** → 实测单张 139–365 ms，20 张推理不到 10 秒；瓶颈在人工递样，不在算力。
3. **"为什么大模型不能直接喷？"** → 安全设计：大模型只出文本建议；喷淋必须过"白名单片区 + 时长钳制 + 人工确认"三道闸，未配置的片区会直接拒绝执行。
